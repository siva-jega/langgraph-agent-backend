Trace a Chat Into LangGraph

Your first win: follow one customer message from the HTTP endpoint into the LangGraph loop.

Mission link: after this lesson, you should know which file to open first when debugging an agent response.

The Five Stops

A chat request does not begin inside LangGraph. It reaches LangGraph only after FastAPI routing and service setup.

FastAPImain.py
Creates the app and mounts routes.
Routeagents/route.py
Receives /api/agents/stream.
Serviceagents/service.py
Loads config and emits SSE.
Graphgraph/graph.py
Runs self.graph.astream(...).
Nodesgraph/nodes.py
Trim, LLM, and tools logic.

The Graph Loop

START -> trim -> llm

if LLM asks for a tool:
  llm -> tools -> trim -> llm

if LLM is done:
  llm -> escalation_check -> END

The important trick is that llm is not always the final answer. Sometimes it produces a tool request. LangGraph sees that request and routes to tools.

Why Tools Work

In nodes.py, _get_tools(config) builds the available tool list from the agent's runtime config: apps, skills, knowledge-base IDs, folder IDs, and human handoff settings.

Then llm_node binds those tools to the model. If the model returns tool calls, tools_condition sends the graph to tools_node, which wraps LangGraph's ToolNode.

Common confusion: the LLM chooses that a tool should be called, but the code executes the tool. That split is the heart of the ReAct loop.

Practice

Question 1: If a user asks "Where is my order?", which node decides whether to call an order-status tool?

Show answer

The llm node. It calls the model with bound tools. The model may return a tool call, then tools_condition routes to tools.

Question 2: Which file contains the actual graph edges?

Show answer

packages/agent/app/modules/agents/graph/graph.py, inside Graph._build_graph().

Question 3: Which layer converts graph chunks into event: chat_message and event: tool_call SSE output?

Show answer

packages/agent/app/modules/agents/service.py, inside process_chat_request().
